# 2026-10-26 金手指：修复点「稍后安排」后仍在播报

## 现象
弹窗打开时立刻播报；点「稍后安排」关掉弹窗后，语音又开始播一遍弹窗内容。

## 原因
语音播报为 iOS Safari 做了「首次交互补播」：`speakModal()` 会把内容存到 `pendingSpeak`，并在 `document` 上挂一次性 `click` 监听，等用户第一次点击时补播。

事件顺序是：按钮的 click（→ `closeReminder()` → `stopSpeak()`）先执行，然后冒泡到 document 的补播监听，于是又把 `pendingSpeak` 播了出来——即使弹窗已经关闭。

## 修复（`assets/goal.js`）
1. `closeReminder()`：关闭时清空 `pendingSpeak`，再 `stopSpeak()`。
2. 补播监听：只有弹窗仍然打开时才补播
```js
var modalOpen = (el.reminder && !el.reminder.hidden) ||
  (el.rewardModal && !el.rewardModal.hidden);
if (modalOpen && speakOn()) speak(pendingSpeak);
pendingSpeak = '';
```
3. `toggleSpeak()`：打开播报时只在还有待播内容（弹窗开着）时补播，不再用 `remindTitle` 兜底，避免弹窗已关还出声。

## 验证（桩替换 `speechSynthesis`，目标「每天读书30页并减脂5斤」）
- 打开弹窗：播报 1 次
- 第一次点击就是「稍后安排」：播报次数仍为 1（不再补播），`cancel` 增加（停止朗读），弹窗关闭
- 重新进入点「已完成」：弹窗关闭 → 奖励弹窗播报 → 收下后下一个今日任务播报，累计 4 次
- 弹窗关闭状态下切换「播报：开/关」：不再发声
- 无控制台报错

`sw.js` 缓存版本 `v22 → v23`。
