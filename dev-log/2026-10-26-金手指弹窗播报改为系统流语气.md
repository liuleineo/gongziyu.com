# 2026-10-26 金手指：弹窗播报改为「系统流」语气

## 需求
弹窗语音播报的语气词优化，参考金手指系统类小说的系统播报口吻。

## 文案（全部以「叮，系统提示，」开头）
| 场景 | 播报 |
| --- | --- |
| 今日日常任务 | 叮，系统提示，今日日常任务已刷新。任务名称：每日阅读30页。任务说明：…。请宿主及时完成，完成后可领取随机奖励。 |
| 阶段任务 | 叮，系统提示，系统发布阶段任务。当前进度：第 1 阶段，共 5 阶段。阶段名称：第1阶段·启动。任务名称：…。任务说明：…。请宿主尽快推进，完成后即可解锁本阶段大奖励。 |
| 小奖励 | 叮，系统提示，任务结算完成，恭喜宿主。系统发放随机奖励：听一首喜欢的歌。备注：…。奖励已存入背包，请宿主查收。 |
| 阶段大奖励 | 叮，系统提示，检测到宿主完成第1阶段·启动，主线进度推进。系统解锁阶段大奖励：买一本心仪的书。奖励说明：…。恭喜宿主，请再接再厉，继续冲刺下一阶段。 |
| 今日任务全清 | 叮，系统提示，今日任务清单已全部完成，系统给予高度评价：宿主今日执行力优秀。明日零点将刷新新的日常任务，请宿主继续保持，早日达成目标。 |

## 改动（`assets/goal.js`）
- 新增播报文案构造器，集中在一个区块里，后续改口吻只动这里：
  - `sysDailyTaskLine(task)` / `sysStageTaskLine(task, stageName, index, total)`
  - `sysSmallRewardLine(reward)` / `sysBigRewardLine(reward)` / `sysTodayDoneLine()`
  - `SYS_BELL = '叮，系统提示，'`
  - `sysDot(text)`：去掉标题/说明末尾已有标点再补一个句号，避免 TTS 把「。。」读成停顿重复
- `openReminder()`：日常 / 阶段分别调用前两个构造器（阶段任务带「第 N 阶段，共 M 阶段」）
- `showRewardQueue()`：小奖励 / 大奖励分别调用对应构造器
- `advanceReminder()`：收工播报改用 `sysTodayDoneLine()`

弹窗界面文案未改动（只调语音）。

## 验证（真实接口，桩替换 `speechSynthesis`）
- 日常、阶段、小奖励、大奖励、收工五种文案均正确播出，无「。。」重复
- 手动把第1阶段前 N-1 个任务标记完成后再走提醒流程，可正常触发大奖励播报
- 无控制台报错

`sw.js` 缓存版本 `v23 → v24`。
