# 2026-10-22 金手指：弹窗内容语音播报

## 方案选择
| 方案 | 成本 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **浏览器 Web Speech API（`speechSynthesis`）** | 0 | 零依赖、零请求、离线可用、可离线缓存 | 音色取决于系统；iOS Safari 需用户交互后才能发声 |
| 服务端 TTS（腾讯云 / 阿里云 / Azure）返回 mp3 | 按量付费 | 音色统一、全端一致、可控语速情感 | 需要新增 Key、接口与音频缓存，增加延迟 |

已采用第一种（Web Speech API），并把服务端方案留作备选入口。

## 改动

### `goal.php`
两个弹窗底部各加一个播报开关：
```html
<button type="button" class="goal-modal-speak" id="remindSpeak">播报：开</button>
<button type="button" class="goal-modal-speak" id="rewardSpeak">播报：开</button>
```

### `assets/goal.js`
- `speakSupported()` / `speakOn()`：能力检测 + 开关状态（localStorage `gongziyu_goal_speak`，默认开）。
- `pickZhVoice()`：从 `getVoices()` 里挑中文音色（`zh*` 或 name 含 Chinese/中文），并监听 `voiceschanged`。
- `speak(text)`：新建 `SpeechSynthesisUtterance`，`lang='zh-CN'`、`rate=1.05`，先 `cancel()` 再 `speak()`；音色赋值单独 try/catch（避免个别浏览器抛错导致整句播不出）。
- `speakModal(text)`：弹窗打开时播报，并把文本存为 `pendingSpeak`；iOS 等需要用户手势的浏览器在首次 `click` 时补播一次。
- `toggleSpeak()` / `updateSpeakLabels()`：切开关、同步两个按钮文案（播报：开 / 播报：关），打开时立即播报当前内容，关闭时 `cancel()`。
- 播报时机：任务弹窗 = "接下来要完成，{阶段}，{任务标题}。{任务说明}"；奖励弹窗 = "奖励已解锁，{奖励名}。{说明}"；两个弹窗关闭时 `stopSpeak()`。

### `assets/goal.css`
- `.goal-modal-speak`：弹窗底部虚线分隔的小号文字按钮。

### `sw.js`
- 缓存版本 `v12 → v13`。

## 验证（Playwright + 桩替换 speechSynthesis）
- 弹窗打开即播报：`接下来要完成，第1阶段·启动，任务1。任务1的说明`，`lang=zh-CN`。
- 关播报：按钮变"播报：关"、localStorage 写 0，之后弹窗不再发声。
- 再打开：立即播报当前弹窗内容（`任务2`）。
- 奖励弹窗：`奖励已解锁，一杯咖啡。即时反馈`。
- 关闭弹窗时调用 `cancel()` 停止朗读；无控制台报错。

## 备选：服务端 TTS 接入点
若以后要换成统一音色，可在 `api/` 新增 `tts.php`：入参文本 → 调云厂商 TTS → 返回 mp3 URL；前端改为 `new Audio(url).play()`，其余开关/队列逻辑不变。注意要给文本做长度限制与缓存（同一文本复用音频）。
